# StoreSense

**AI-аналитика магазина по уже установленным камерам.** Считает посетителей, показывает горячие зоны отделов, находит пустые полки и оценивает, как быстро продавцы подходят к покупателям. Каждый вечер присылает короткий отчёт в Telegram, который пишет локальная модель в Ollama.

> Store analytics from existing CCTV cameras: footfall, department heatmaps, empty-shelf alerts and service-time metrics, with daily AI reports in Telegram. Runs fully on-premise with Docker and Ollama.

Сделано для сети детских магазинов Mittivoy (Ташкент).

## Что умеет

| Модуль | Что показывает | Статус |
|---|---|---|
| Посетители | вход/выход, по часам, сравнение с прошлой неделей, сейчас в магазине | ✅ дашборд и отчёты, 🔜 счётчик по камере |
| Горячие зоны | посещения и время в каждом отделе, тепловая карта зала | ✅ дашборд, 🔜 зоны по камере |
| Полки | полная / мало / пустая, алерт в Telegram | ✅ дашборд и алерты, 🔜 проверка снимков через Ollama Vision |
| Консультации | % покупателей без консультации, ожидание продавца | ✅ дашборд, 🔜 детекция по камере |
| AI-отчёты | ежедневный отчёт и алерты в Telegram | ✅ Ollama, без неё — по шаблону |

Пока камеры не подключены, вместо них работает **симулятор**: генерирует правдоподобные события, поэтому всю систему можно посмотреть и показать уже сейчас.

## Приватность

- Видео не сохраняется, лица не распознаются, люди не идентифицируются. В базе только обезличенные события: время, отдел, числа.
- Всё работает локально, данные не уходят в облако. В Ollama отправляются только цифры.
- Зоны размечаются только в торговом зале. Примерочные не снимаются и не анализируются.
- Статистика ведётся по филиалам и отделам, а не по конкретным сотрудникам.

## Быстрый старт

Нужен только [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Windows / macOS) или Docker на Linux.

**Windows:** дважды кликни `start.bat`.
**Linux / macOS:** `./start.sh`

Или вручную:
```bash
cp .env.example .env
docker compose up -d --build
```

Через минуту открой **http://localhost:8080**. При первом запуске симулятор заполнит историю за 14 дней, а reporter скачает модель для Ollama (около 2 ГБ, один раз).

Всё поднимается автоматически после перезагрузки компьютера и после сбоев (`restart: unless-stopped`), логи ограничены по размеру.

## Настройка

**`config/config.yaml`** — филиалы, камеры, отделы, полки, время отчёта, алерты. API перечитывает файл сам, перезапуск не нужен.

**`.env`** — Telegram, модель Ollama, порт, режим:

```env
COMPOSE_PROFILES=demo          # demo = симулятор, cameras = настоящие камеры
TELEGRAM_BOT_TOKEN=123:ABC     # бот от @BotFather
TELEGRAM_CHAT_ID=-100123456    # группа, куда слать отчёты
OLLAMA_MODEL=qwen2.5:3b        # с видеокартой можно qwen2.5:7b
```

После изменения `.env`: `docker compose up -d`.

Отчёт прямо сейчас, не дожидаясь вечера:
```bash
docker compose exec reporter python reporter.py --once
```

## Архитектура

```
Камеры (RTSP) ─→ counter (YOLO + трекинг) ─┐      [следующий этап]
                                            ├─→ api (Starlette + SQLite) ─→ дашборд :8080
симулятор (сейчас) ─────────────────────────┘          │
                                                       └─→ reporter ─→ Ollama ─→ Telegram
```

| Сервис | Что делает |
|---|---|
| `api` | принимает события, считает метрики, отдаёт дашборд |
| `simulator` | заменяет камеры, пока их нет (профиль `demo`) |
| `reporter` | ежедневный AI-отчёт и алерты: пустая полка, камера отключилась, нет посетителей |
| `ollama` | локальная языковая модель |
| `counter` | подсчёт по реальным камерам (профиль `cameras`, следующий этап) |

### Формат событий

Счётчик по камерам будет слать в `POST /api/events` то же, что и симулятор:

```json
{"events": [
  {"ts": 1792760000, "branch": "chilanzar", "camera": "entrance", "type": "entry"},
  {"ts": 1792760040, "branch": "chilanzar", "camera": "hall", "type": "zone_visit", "zone": "toys", "value": 230},
  {"ts": 1792760100, "branch": "chilanzar", "camera": "hall", "type": "consult", "zone": "toys", "value": 95,
   "data": {"consulted": true, "duration": 160}},
  {"ts": 1792760200, "branch": "chilanzar", "camera": "shelves", "type": "shelf", "zone": "girls",
   "data": {"shelf": "g-1", "status": "empty"}}
]}
```

Типы: `entry`, `exit`, `zone_visit`, `consult`, `shelf`, `heartbeat`.

### API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/dashboard?branch=&date=` | все метрики филиала за день |
| GET | `/api/config` | конфиг без RTSP-паролей |
| POST | `/api/events` | приём событий (ключ `X-API-Key`, если задан `API_KEY`) |
| GET/POST | `/api/reports` | отчёты и алерты |
| GET | `/api/health` | проверка работы |
